**Franklin–Reiter Related-Message Attack** 是針對 RSA 加密演算法的一種經典密碼分析攻擊。

當攻擊者攔截到**兩個不同的密文**，且知道這兩份明文之間存在某種**已知線性關係**（且使用了相同的公鑰 $n, e$），攻擊者就能在不用分解 $n$、也不需要知曉私鑰 $d$ 的情況下，直接還原出原始明文。

## 攻擊情境與條件

假設發送方對兩個相關訊息 $m_1$ 與 $m_2$ 進行加密：

1. **已知線性關係**：
   $m_2 = f(m_1) \pmod n$，其中 $f(x) = ax + b$ 是公開或攻擊者已知的一次方多項式（例如 $m_2 = m_1 + 100$）。

2. **相同的公鑰**：
   兩者皆使用相同的模數 $n$ 與相同的加密指數 $e$（通常 $e$ 較小，如 $e = 3$）。

3. **攔截到的密文**：
$$c_1 \equiv m_1^e \pmod n$$
$$c_2 \equiv m_2^e = (f(m_1))^e \pmod n$$
## 數學原理與破解過程

攻擊的核心思想是將「RSA 加密」轉換成求「**多項式最大公因式（GCD）**」的問題：

1. **建立多項式**：
    定義兩個以 $x$ 為未知數的多項式：
$$g_1(x) = x^e - c_1 \pmod n$$
$$g_2(x) = (ax + b)^e - c_2 \pmod n$$
2. **分析根（Roots）**：
    - 當 $x = m_1$ 時：$g_1(m_1) = m_1^e - c_1 \equiv 0 \pmod n$。
    - 當 $x = m_1$ 時：$g_2(m_1) = (a m_1 + b)^e - c_2 = m_2^e - c_2 \equiv 0 \pmod n$。
        
        因此，$x = m_1$ 同時是 $g_1(x)$ 與 $g_2(x)$ 在模 $n$ 下的**公共根**（Common Root）。

3. **求最大公因式（Polynomial GCD）**：
    
    若 $e$ 足夠小（例如 $e = 3$），攻擊者可以利用歐幾里得演算法計算兩個多項式的最高公因式：
    $$g(x) = \gcd(g_1(x), g_2(x)) \pmod n$$
    如果次數滿足條件，求出的 $\gcd$ 多項式會是一次式 $(x - m_1)$。

4. **提取明文**：
    
    直接從 $(x - m_1)$ 中取出常數項，即可直接還原出明文 $m_1$！

## 核心原理拆解

### 1. 為何 $x = m_1$ 是公共根？

我們建立的兩個多項式分別為：
- $g_1(x) = x^e - c_1 \pmod n$
- $g_2(x) = (ax + b)^e - c_2 \pmod n$
我們知道：
1. $c_1 \equiv m_1^e \pmod n$，所以把 $x = m_1$ 代入 $g_1(x)$：$$g_1(m_1) = m_1^e - c_1 \equiv 0 \pmod n$$
2. $m_2 = a m_1 + b$，且 $c_2 \equiv m_2^e \pmod n$，所以把 $x = m_1$ 代入 $g_2(x)$：
    $$g_2(m_1) = (a m_1 + b)^e - c_2 = m_2^e - c_2 \equiv 0 \pmod n$$
因為代入 $x = m_1$ 都會讓兩個多項式等於 0，根據代數的**因式定理**：
> $(x - m_1)$ 必定同時是 $g_1(x)$ 和 $g_2(x)$ 的因式（Factor）。

### 2. 為什麼 $\gcd$ 「剛好」是一次式 $(x - m_1)$？

既然 $(x - m_1)$ 是公因式，那最大公因式（GCD）的次數至少是 1。但為什麼不會是二次式、三次式或更高的次數呢？
- $g_1(x) = 0$ 在模 $n$ 下可能有多個根（最多 $e$ 個）。
- $g_2(x) = 0$ 在模 $n$ 下也有自己的一組根。
- 在密碼學隨機明文的條件下，$g_1(x)$ 與 $g_2(x)$ **「同時擁有其他相同根」的機率極低**。
因此，除了真正的明文 $x = m_1$ 之外，這兩個多項式幾乎不可能再共享其他的根。所以它們的「最高公因式」就只有這唯一的交集：

$$\gcd(g_1(x), g_2(x)) = (x - m_1)^1 = x - m_1$$

## 具體數字手算範例（Toy Example）

為了直觀理解，我們設定一組極小的數字來模擬整個過程：

- **設定參數：**
    - 模數 $n = 35$ （$p=5, q=7$）
    - 加密指數 $e = 3$
    - 秘密明文 $m_1 = 6$
    - 線性關係：$m_2 = m_1 + 1 = 7$（$a=1, b=1$）
- **加密過程：**
    - $c_1 = m_1^3 = 6^3 = 216 \equiv 6 \pmod{35}$
    - $c_2 = m_2^3 = 7^3 = 343 \equiv 28 \pmod{35}$
- **建立多項式：**
    - $g_1(x) = x^3 - 6 \pmod{35}$
    - $g_2(x) = (x + 1)^3 - 28 = x^3 + 3x^2 + 3x + 1 - 28 = x^3 + 3x^2 + 3x - 27 \pmod{35}$

- **求 $\gcd(g_1(x), g_2(x))$ 的輾轉相除步驟：
      
    1. **第一步（消去 $x^3$ 項）：**$$r_1(x) = g_2(x) - g_1(x) = (x^3 + 3x^2 + 3x - 27) - (x^3 - 6) = 3x^2 + 3x - 21 \pmod{35}$$
    2. **簡化 $r_1(x)$（使其首項係數為 1）：**
        我們需要 $3$ 在 $\pmod{35}$ 下的反元素。因為 $3 \times 12 = 36 \equiv 1 \pmod{35}$，所以將多項式乘以 $12$：$$12 \cdot (3x^2 + 3x - 21) \equiv x^2 + x - 252 \equiv x^2 + x - 7 \pmod{35}$$
        得到新餘式 $r_1'(x) = x^2 + x - 7$。
    3. **第二步（用 $g_1(x)$ 除以 $r_1'(x)$）：**$$g_1(x) = x(x^2 + x - 7) - (x^2 - 7x + 6)$$
        再扣掉一次 $r_1'(x)$ 消去二次項：$$-(x^2 - 7x + 6) - (-1)(x^2 + x - 7) = 8x - 13 \pmod{35}$$
    4. **簡化最後得到的一次式：**
        我們需要 $8$ 在 $\pmod{35}$ 下的反元素。因為 $8 \times 22 = 176 \equiv 1 \pmod{35}$，將式子乘以 $22$：$$22 \cdot (8x - 13) = 176x - 286 \equiv 1x - 6 = x - 6 \pmod{35}$$
最終求得的 $\gcd$ 恰好就是：
$$g(x) = x - 6$$

直接取常數項的負數，就得到了明文 **$m_1 = 6$**！
## 補充：如果在模 $n$ 下輾轉相除法失敗了怎麼辦？

因為 $n = pq$ 不是質數（不構成體 Field），在多項式除法過程中，我們有時需要求某個係數在 $\pmod n$ 下的反元素（乘法逆元）。

如果在計算反元素時失敗了（即 $\gcd(\text{係數}, n) \neq 1$），這意味著我們**意外找到了 $n$ 的因數 $p$ 或 $q$**！這種情況下 RSA 直接被徹底破譯，同樣達成了攻擊目的。

## 時間複雜度與限制

- **時間複雜度**：計算兩個多項式的 GCD 只需要 $\tilde{O}(e^2)$ 或 $\tilde{O}(e)$ 時間。只要 $e$ 很小（例如 $e = 3$ 或 $e = 17$），可以在幾毫秒內算出解答。 
    
- **主要限制**：若公鑰指數 $e$ 太大（例如常見的 $e = 65537$），多項式的展開與 $\gcd$ 運算的複雜度會變得非常高，此攻擊就會變得不可行。

## 防禦方法

1. **使用隨機填充（Random Padding）**：
    採用 **OAEP（Optimal Asymmetric Encryption Padding）** 填充標準。每次加密時都會加入高強度的隨機位元，破壞 $m_1$ 與 $m_2$ 之間的已知線性關係，使 $f(x)$ 無法建立。

2. **避免重複使用 $n$ 與小 $e$ 加密結構相似的訊息**。

這裡的關鍵在於「因式定理（Factor Theorem）」**與**「多項式的歐幾里得演算法（Euclidean Algorithm）」的結合。

  
簡單來說：**如果 $x = m_1$ 是兩個多項式的共同零點（根），那麼 $(x - m_1)$ 就必然是這兩個多項式的公因式。**

## 找多項式的 GCD 方法

### 方法一：Sage

#### 前置作業

1. Anaconda 建立 sage 環境
```bash
conda create -n sage -c conda-forge sage python=3.11
```

2. 啟用 sage
```bash
conda activate sage
```

#### 編寫程式（範例）

**solve.sage**
```python
N = 11413
e = 3

c1 = 5610
c2 = 1106

delta = 5

R.<x> = PolynomialRing(Zmod(N))

f = x^e - c1
g = (x + delta)^e - c2

h = gcd(f, g)

print(h)
```

#### 執行

```bash
sage solve.sage
```

結果：

```text
x + 11371
```

注意係數是在 mod (11413) 下：$11371\equiv -42\pmod{11413}$

所以：$h(x)=x-42$

因此可以取：

```python
m1 = -h[0] % N
print(m1)
```

得到：

```text
42
```

## 跟其他 RSA Attack 的差別

幾種 CTF 常見 RSA 弱點不要混在一起：

| Attack                  | 條件                  |
| ----------------------- | ------------------- |
| Wiener Attack           | $d$ 太小              |
| Fermat Factorization    | $p,q$ 非常接近          |
| Hastad Broadcast Attack | 同一明文、不同 $N$、小 $e$   |
| Common Modulus Attack   | 同一 $N$、同一明文、不同 $e$  |
| Franklin–Reiter         | 同一 $N,e$，明文具有已知關係   |
| Coppersmith             | 已知部分明文 / 小未知根等      |
| Shared Prime Attack     | 不同 $N$ 共用 $p$ 或 $q$ |


所以看到：

```text
同一個 N
同一個 e
兩個 ciphertext
知道 m1 - m2
```

應該第一時間想到：$\boxed{\text{Franklin–Reiter Related-Message Attack}}$

尤其像 $e=3,5,17$ 這類次數並不高時，多項式 GCD 非常容易計算；**(e=0x11=17) 也完全是合理的 Franklin–Reiter 題目**。
