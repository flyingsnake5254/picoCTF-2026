在 CTF 裡遇到「圖片題」，不要只把它當圖片看，通常要把它當成一個 **二進位檔案 + 圖片格式 + 隱寫載體** 來分析。

我會把圖片 CTF 的探查面向分成下面這幾層：

| 層次              | 探查什麼                      | 常用工具                               |
| --------------- | ------------------------- | ---------------------------------- |
| 1. 檔案本身         | 真實格式、magic bytes、大小       | `file`, `xxd`                      |
| 2. Metadata     | EXIF、Comment、Author、GPS   | `exiftool`                         |
| 3. 可讀字串         | flag、password、URL         | `strings`                          |
| 4. 檔案結構         | PNG chunk、JPEG segment    | `pngcheck`, `jpeginfo`             |
| 5. 內嵌檔案         | ZIP、RAR、另一張圖片             | `binwalk`, `foremost`, `7z`        |
| 6. 隱寫術          | LSB、RGB channel、bit plane | `zsteg`, StegSolve, `stegoveritas` |
| 7. Steghide 類   | JPEG/BMP 隱藏資料             | `steghide`, `stegseek`             |
| 8. 視覺資訊         | 亮度、色彩、透明度                 | StegSolve, ImageMagick             |
| 9. QR / Barcode | QR Code、條碼                | `zbarimg`                          |
| 10. 文字辨識        | 圖片中的文字                    | `tesseract`                        |

---

# 1. 第一件事：確認它到底是不是圖片

例如題目給：

```text
flag.jpg
```

不要相信副檔名。

先：

```bash
file flag.jpg
```

可能得到：

```text
flag.jpg: PNG image data, 800 x 600, 8-bit/color RGB
```

代表：

```text
副檔名：JPG
實際格式：PNG
```

這本身就可能是提示。

也可以：

```bash
xxd flag.jpg | head
```

常見 [[Magic Bytes]]：

```text
JPEG
FF D8 FF

PNG
89 50 4E 47 0D 0A 1A 0A

GIF
47 49 46 38

ZIP
50 4B 03 04

RAR
52 61 72 21
```

例如：

```text
00000000: 8950 4e47 0d0a 1a0a ...
```

看到：

```text
89 50 4E 47
```

就是 PNG。

# 2. Metadata：`exiftool`

圖片 CTF **第一批必跑工具**之一：

```bash
exiftool flag.jpg
```

可以看到：

```text
File Name
File Size
Image Width
Image Height
Camera Model
Software
Artist
Comment
Description
GPS
Create Date
Modify Date
```

CTF 很可能直接把東西藏在：

```text
Comment
Artist
Copyright
Description
UserComment
Software
```

例如：

```text
Comment : flag{metadata_is_easy}
```

也可以指定：

```bash
exiftool -Comment flag.jpg
```

或：

```bash
exiftool -a -u -g1 flag.jpg
```

其中：

```text
-a    顯示重複 tag
-u    顯示未知 tag
-g1   分組
```

CTF 建議直接：

```bash
exiftool -a -u -g1 flag.jpg
```

---

# 3. 找所有可讀字串：`strings`

非常重要：

```bash
strings flag.jpg
```

更常用：

```bash
strings -n 6 flag.jpg
```

意思是至少 6 個字元才顯示。

找 flag：

```bash
strings flag.jpg | grep -i flag
```

也可以找：

```bash
strings flag.jpg | grep -Ei 'flag|password|pass|key|secret'
```

CTF 裡很常發生：

```text
圖片正常
+
檔案尾端直接塞了一段

flag{hello_world}
```

肉眼完全看不到，但是：

```bash
strings image.png
```

直接找到。

---

# 4. 看 Hex：`xxd`

如果 `strings` 找不到，可以直接看二進位。

```bash
xxd flag.png | less
```

或者：

```bash
hexdump -C flag.png | less
```

特別注意：

```text
Header
Footer
EOF 後面
```

例如 JPEG 正常結尾：

```text
FF D9
```

但是可能：

```text
FF D9
50 4B 03 04
```

這很可疑。

因為：

```text
FF D9
→ JPEG 結尾

50 4B 03 04
→ ZIP 開頭
```

代表可能是：

```text
JPEG
│
├─ 正常圖片
│
└─ ZIP
```

也就是：

```text
image.jpg
=
JPEG + ZIP
```

---

# 5. 搜尋內嵌檔案：`binwalk`

這是 CTF 圖片題非常重要的工具。

```bash
binwalk flag.jpg
```

可能：

```text
DECIMAL       HEXADECIMAL
-----------------------------------
0             0x0       JPEG image
154823        0x25CC7   Zip archive
```

這代表：

```text
0 ~ 154822
    JPEG

154823 ~
    ZIP
```

可以嘗試自動解：

```bash
binwalk -e flag.jpg
```

或進一步：

```bash
binwalk -eM flag.jpg
```

常見內嵌：

```text
ZIP
RAR
7z
PDF
ELF
PNG
JPEG
gzip
tar
SQLite
```

---

# 6. 手動切檔：`dd`

如果 binwalk 告訴你：

```text
ZIP at offset 154823
```

可以：

```bash
dd if=flag.jpg of=hidden.zip bs=1 skip=154823
```

然後：

```bash
file hidden.zip
```

再：

```bash
unzip hidden.zip
```

所以 CTF 裡要熟悉：

```text
Offset
```

例如：

```text
0x25CC7
```

就是檔案內某個位置。

---

# 7. `foremost` / carving

另一種方式是直接做 File Carving：

```bash
foremost flag.jpg
```

它會根據：

```text
Header
Footer
Magic bytes
```

嘗試挖出裡面的：

```text
jpg
png
zip
pdf
gif
...
```

概念：

```text
image.png
│
├── PNG
├── ZIP
├── JPG
└── PDF

          ↓

       foremost

          ↓

output/
├── jpg/
├── png/
├── zip/
└── pdf/
```

# 8. PNG 特別重要：`pngcheck`

如果是：

```text
PNG
```

建議：

```bash
pngcheck -v flag.png
```

PNG 是由很多 Chunk 組成：

```text
PNG Signature
      │
      ▼
IHDR
      │
      ▼
PLTE
      │
      ▼
IDAT
      │
      ▼
IEND
```

正常最重要：

```text
IHDR
IDAT
IEND
```

但可能還有：

```text
tEXt
zTXt
iTXt
```

例如：

```text
tEXt
Comment
flag{...}
```

這就是經典藏法。

---

# 9. PNG / BMP 的 LSB：`zsteg`

如果題目開始進入真正「Steganography」，PNG/BMP 第一個想到：

```bash
zsteg flag.png
```

例如：

```text
b1,r,lsb,xy  .. text: "flag{hidden_in_lsb}"
```

暴力檢查更多模式：

```bash
zsteg -a flag.png
```

這個在 CTF 非常實用。

它會嘗試：

```text
R channel
G channel
B channel
Alpha

LSB
MSB

bit 1
bit 2
...

不同 pixel order
```

---

# 10. 什麼是 LSB？

例如像素：

```text
R = 11010110
G = 10101001
B = 01101100
```

最低位：

```text
R → 0
G → 1
B → 0
```

把大量 pixel 的最後一 bit 收集：

```text
01001100 01000001 ...
```

可能還原成：

```text
FLAG{...}
```

這就是：

> Least Significant Bit Steganography

因為 RGB 改：

```text
100 → 101
```

人眼幾乎看不出差異。

---

# 11. StegSolve：看 Color Channel / Bit Plane

CTF 非常經典。

StegSolve 可以切：

```text
Red Plane
Green Plane
Blue Plane
Alpha Plane
```

也可以看：

```text
Red bit 0
Red bit 1
...
Red bit 7

Green bit 0
...

Blue bit 0
...
```

常常你原圖看到：

```text
██████████
看起來完全正常
```

結果：

```text
Blue Plane 0
```

突然出現：

```text
FLAG
```

所以肉眼沒看到東西，不代表圖片真的沒東西。

---

# 12. `stegoveritas`

另一個自動化圖片隱寫分析工具。

典型：

```bash
stegoveritas flag.png
```

它會嘗試進行多種分析，例如：

```text
Metadata
Trailing data
Color planes
Bit planes
LSB
File carving
Image transformations
```

適合一開始快速掃描。

可以理解成：

```text
           stegoveritas
                │
     ┌──────────┼──────────┐
     ↓          ↓          ↓
 Metadata    Carving    Bit Plane
                            │
                            ↓
                          LSB
```

---

# 13. JPEG / BMP：`steghide`

如果題目是：

```text
.jpg
.jpeg
.bmp
.wav
.au
```

很值得試：

```bash
steghide info flag.jpg
```

可能：

```text
embedded file "secret.txt":
    size: 32 Bytes
    encrypted: rijndael-128
```

解出：

```bash
steghide extract -sf flag.jpg
```

接著：

```text
Enter passphrase:
```

如果密碼正確：

```text
wrote extracted data to "secret.txt".
```

---

# 14. `stegseek`：爆 Steghide 密碼

如果：

```bash
steghide info flag.jpg
```

確認裡面有資料，但不知道 password，可以考慮：

```bash
stegseek flag.jpg rockyou.txt
```

Kali 常見字典：

```text
/usr/share/wordlists/rockyou.txt
```

因此：

```bash
stegseek flag.jpg /usr/share/wordlists/rockyou.txt
```

成功可能：

```text
Found passphrase: "secret123"
Original filename: "flag.txt"
```

然後取得：

```text
flag.txt
```

# 15. QR Code / Barcode

圖片裡如果看到：

```text
QR
Barcode
Data Matrix
```

可以：

```bash
zbarimg flag.png
```

例如：

```text
QR-Code:flag{qr_code}
```

有些 CTF 會：

```text
QR 太淡
QR 反色
QR 拆成 RGB channel
QR 藏在 bit plane
```

所以：

```text
原圖
 ↓
StegSolve
 ↓
Blue Plane
 ↓
QR Code
 ↓
zbarimg
 ↓
flag
```

這種組合很常見。

# 16. 圖片裡直接藏文字：OCR

有時候文字非常小、模糊或很多。

可以用：

```bash
tesseract flag.png stdout
```

例如：

```text
flag{hidden_text}
```

也可以先：

```text
放大
提高對比
灰階化
```

再 OCR。

# 17. ImageMagick

圖片轉換、分離 Channel 很方便。

查看圖片資訊：

```bash
identify flag.png
```

詳細：

```bash
identify -verbose flag.png
```

新版通常也可以：

```bash
magick identify -verbose flag.png
```

分離 RGB：

```bash
magick flag.png -channel R -separate red.png
magick flag.png -channel G -separate green.png
magick flag.png -channel B -separate blue.png
```

有 Alpha：

```bash
magick flag.png -channel A -separate alpha.png
```

這很適合找：

```text
Red channel
Green channel
Blue channel
Alpha channel
```

中的隱藏資訊。

---

# 18. 圖片尺寸也可能被動過手腳

例如 PNG：

```text
實際圖片資料
1920 × 1080

IHDR 卻被改成
1920 × 500
```

結果下半部根本沒顯示。

因此：

```bash
pngcheck -v flag.png
```

和：

```bash
identify flag.png
```

都很重要。

有時需要修改：

```text
width
height
```

才能看到完整圖片。

JPEG 也可能有類似：

```text
高度錯誤
檔案截斷
header 損壞
```

---

# 19. Alpha Channel

透明圖片尤其注意。

肉眼看到：

```text
完全透明
```

不代表沒有 RGB 資訊。

可能：

```text
R G B = FLAG 圖案
Alpha = 0
```

所以畫面什麼都沒有。

可以：

```bash
magick flag.png -alpha off visible.png
```

或直接用 StegSolve 查看：

```text
Alpha Plane
RGB Plane
```

---

# 20. 檔案尾端

這個是非常非常常見的 CTF 技巧。

例如：

```text
PNG
│
├─ Signature
├─ IHDR
├─ IDAT
├─ IEND
│
└────────────── ZIP
```

PNG 正常到：

```text
IEND
```

就結束。

但是攻擊者可能：

```bash
cat image.png secret.zip > flag.png
```

因此：

```bash
binwalk flag.png
```

可能直接看到：

```text
PNG image
ZIP archive
```

# 一套 CTF 圖片分析 SOP

我會建議你拿到圖片後按照這個順序：

```text
                    image
                      │
            ┌─────────▼─────────┐
            │ ① 基本檔案資訊    │
            └─────────┬─────────┘
                      │
      file / identify / xxd
                      │
                      ▼
            ② Metadata
                      │
                  exiftool
                      │
                      ▼
            ③ Strings
                      │
                  strings
                      │
                      ▼
            ④ 檔案結構
                      │
       pngcheck / jpeginfo
                      │
                      ▼
            ⑤ Embedded Files
                      │
          binwalk / foremost
                      │
                      ▼
            ⑥ Steganography
                      │
       ┌──────────────┼───────────────┐
       ↓              ↓               ↓
     zsteg         steghide        StegSolve
    PNG/BMP        JPG/BMP        Bit Planes
       │              │
       │              ▼
       │           stegseek
       │
       ▼
     LSB
       │
       ▼
  RGB / Alpha
       │
       ▼
 QR / text / file
```

## 我自己在 Kali 遇到圖片題，第一輪通常會跑

```bash
file flag.png
exiftool -a -u -g1 flag.png
strings -n 6 flag.png | less
xxd flag.png | head
binwalk flag.png
identify -verbose flag.png
```

如果是 PNG：

```bash
pngcheck -v flag.png
zsteg flag.png
zsteg -a flag.png
```

如果是 JPG/BMP：

```bash
steghide info flag.jpg
```

如果確認是 Steghide：

```bash
stegseek flag.jpg /usr/share/wordlists/rockyou.txt
```

如果還找不到：

```text
StegSolve
↓
RGB channels
↓
Alpha
↓
Bit planes
↓
LSB/MSB
↓
QR / Barcode
```

### CTF 圖片題最值得優先懷疑的 8 個地方

1. **Metadata / Comment**
    
2. **檔案尾端追加資料**
    
3. **內嵌 ZIP / RAR / 其他圖片**
    
4. **PNG `tEXt` 等 Chunk**
    
5. **LSB**
    
6. **RGB / Alpha Channel**
    
7. **Steghide**
    
8. **圖片尺寸或 Header 被竄改**
    

如果這 8 類都會查，已經能處理相當大一部分入門到中階的 CTF Image Forensics / Steganography 題目。
